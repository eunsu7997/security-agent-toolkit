# 2026-10-19 (월)

오전: Zero Trust · 점수로 판단하는 함수(PDP) · A사 적용 방안
오후: Docker ① · nginx 서버 켜고 접속 기록 읽기 · 내 폴더 연결

## 오늘 새로 쓴 명령
docker --version, docker run, docker images, docker ps (-a), docker pull, docker logs, docker exec, docker stop, docker rm

## 오늘 쓴 옵션
- `-d` : 컨테이너를 뒤에서 실행해 터미널을 계속 쓴다
- `--name web` : 컨테이너에 이름을 붙인다(logs·stop·rm 에 이 이름을 쓴다)
- `-p 8080:80` : 내 PC 8080 포트를 컨테이너 80 포트로 연결한다
- `-v "$(pwd)/site-one:/usr/share/nginx/html:ro"` : 내 폴더를 컨테이너 폴더에 읽기 전용(`:ro`)으로 연결한다
- `-it` : 컨테이너 안 터미널을 키보드로 쓴다 / `rm -f` : 켜져 있어도 끄고 지운다

## 찾아보고 알게 된 것
- Zero Trust 는 "사내망 안이면 믿는다"가 아니라 요청마다 ID·Device·Network·Application·Policy 를 확인한다.
  새벽 사건은 출발 IP 가 사내 대역이라 방화벽을 통과했지만, 미등록 기기·MFA 없음·맡지 않은 자원 조회가 걸러지지 않았다.
- 판정 규칙의 점수는 하나의 정답이 아니라, 기대 결정을 모두 만족하는 범위다(기기 이상 ≥50, MFA·해외 각 10~49, 둘의 합 ≥50).
- 판단하는 곳(PDP)과 막는 곳(PEP)을 나누면 규칙을 한 곳에서 고쳐도 모든 PEP 가 따른다. A사 ZT 성숙도는 30/100, 먼저 올릴 항목은 Device.
- 이미지는 읽기 전용 묶음이고, 컨테이너는 그 이미지를 실행할 때마다 하나씩 생긴다. 끝나도 `ps -a` 에 남는다.
- 컨테이너 안에서 고친 파일은 컨테이너를 지우면 사라진다. 지켜야 할 파일은 내 PC 에 두고 `-v` 로 연결한다.
- 서버 두 대는 같은 이미지(nginx:1.28)로 띄우고 내 PC 포트(8080·8081)로 구분한다.

## 막힌 것
- 포트 없이 켠 nginx 는 Up 인데 접속이 안 됐다. `docker ps` 의 PORTS 에 `80/tcp` 만 있고 `->` 가 없었다.
  → `-p 8080:80` 으로 연결하니 `0.0.0.0:8080->80/tcp` 가 되고 접속됐다.
- 같은 이름으로 다시 `docker run` 하니 `Conflict. The container name "/web" is already in use` 가 나왔다.
  → 꺼진 컨테이너도 이름을 차지하고 있어서 `docker rm web` 으로 지운 뒤 다시 켰다.
- Git Bash 에서 `-v` 로 연결했는데 화면이 그대로 Welcome to nginx! 였다. Git Bash 가 컨테이너 쪽 경로를
  `C:/Program Files/Git/usr/share/nginx/html` 로 바꿔 버렸기 때문이다. `docker exec web ls /usr/share/nginx/html` 도 같은 이유로 실패했다.
  → 명령 앞에 `MSYS_NO_PATHCONV=1` 을 붙여 해결했다.
