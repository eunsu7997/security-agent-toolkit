## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답:

```python
def jitter(got):
    """받은 응답 시간 리스트로 지터를 구한다.

    입력: 응답을 받은 값만 모은 응답 시간 리스트 got (ms)
    리턴: 이웃한 두 값의 차이(절댓값)의 평균, 즉 지터 (ms)
    """
    total = 0
    for i in range(1, len(got)):
        total = total + abs(got[i] - got[i - 1])
    return total / (len(got) - 1)
```

- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답:
    ```
    회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
    회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
    회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
    ```
- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답: ① 이웃한 두 응답 시간의 차이(절댓값)의 평균, 즉 지터 값을 리턴합니다. ② `measure` 안의 `jitter_value = jitter(got)` 줄에서 받아 `jitter_value` 에 담고, 마지막 `print` 줄에서 `round(jitter_value, 1)` 로 지터 값을 출력합니다.

### 문제 6-2 · 세 회선을 화상회의 기준으로 판정하기

- (가) 세 회선의 판정 결과(적합 · 부적합)와 걸린 기준을 각각 적어 주세요.

- (나) 회선 C 는 지연과 지터가 작은데도 왜 부적합인가요? 어제(10/15) 오후 문제 5-2 에서 본 것과 연결해 적어 주세요.
  - 쓸 내용: ① C 의 손실률과 기준 ② 손실이 통신에 주는 영향 한 가지
  - 답: ① 회선 C 는 지연 41.0 ms · 지터 1.7 ms 로 작지만, 손실률이 30 % 로 기준 1 % 를 크게 넘습니다. ② 어제 오후 문제 5-2 에서 본 `tcp.analysis.retransmission` 처럼 손실된 패킷은 다시 보내야 하고, 실시간 화상회의에서는 도착하지 못한 조각이 화면과 음성의 끊김으로 바로 나타납니다.
- (다) 🔍 `ok` 를 `and` 로 이은 이유는 무엇인가요? `or` 로 이으면 회선 B 의 판정이 어떻게 달라지나요?
  - 쓸 내용: ① `and` 로 이은 이유 ② `or` 로 이으면 B 의 판정이 어떻게 달라지는지
  - 답: ① 화상회의는 지연 · 지터 · 손실 세 기준을 모두 지켜야 쓸 수 있으므로, 세 비교가 모두 `True` 일 때만 `True` 가 되는 `and` 로 이었습니다. 하나라도 넘으면 부적합입니다. ② `or` 로 이으면 하나만 지켜도 `True` 가 되어, 회선 B 는 지연 42.3 ms 가 기준 이하라서 지터 54.3 ms 가 기준을 넘는데도 적합으로 잘못 판정됩니다.

  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(어느 회선이 되고 안 되는지, 이유 한 가지)
  - 답: 회선 A 는 화상회의에 쓸 수 있고, 회선 B 는 지터(54.3 ms)가 커서, 회선 C 는 손실(30 %)이 커서 화상회의에 쓸 수 없습니다.

  - 쓸 내용: 자유롭게
  - 답: 차이를 구할 때 `abs()` 를 쓰지 않으면 오르내림이 서로 상쇄되어 지터가 작게 나오고, 여러 기준을 모두 지켜야 할 때는 `and` 로 이어야 한다는 것을 알았습니다.

  - 쓸 내용: ① 「사내 / 바깥」 하나 ② 근거(사내 홉의 시간 또는 장비 이름)

  - 답: ① 4 번 홉 바로 뒤의 5 번 홉은 7 ms, 6 번 홉은 8 ms 로 다시 작아집니다. ② 뒤쪽 홉은 4 번 장비를 지나서 가는데도 빠르므로, 4 번 장비는 지나가는 패킷은 빨리 넘기고 자기가 보내는 tracert 응답만 늦게 만든 것입니다. 그래서 실제 장애가 아닙니다.

### 2. 세 숫자 판정 — 문제 6-2

- 세 회선의 판정과 걸린 기준을 적고, 세 숫자의 차이를 정리해 주세요.
  - 쓸 내용: ① A · B · C 의 판정과 걸린 기준 ② 지연 · 지터 · 손실이 각각 무엇을 나타내는지
  - 답: ① 회선 A 적합 / 회선 B 부적합(걸린 기준: 지터 54.3 ms) / 회선 C 부적합(걸린 기준: 손실 30 %). ② 지연은 왕복에 걸린 시간의 평균(늦게 도착함), 지터는 이웃한 응답 시간 차이의 평균(도착 시간이 들쭉날쭉함), 손실은 응답이 오지 않은 비율(아예 도착하지 않음)입니다. 평균 지연이 낮아도 지터나 손실이 크면 화상회의가 끊깁니다.

### 3. 지연 원인 — 문제 7-1 · 7-2

- SaaS 접속이 느린 원인 구간과 그 근거를 적어 주세요.

  - 답: ① 통신사 중계 장비(4 번 홉)와 해외 연결 지점(5 번 홉) 사이. ② tracert 에서 6 ms → 48 ms 로 뛰고 6 · 7 번 홉까지 49 · 50 ms 로 유지되며, ping 평균도 평소 22 ms 에서 52 ms 로 늘었습니다. ③ 사내 공유기(1 번 홉) 1 ms · 사내 방화벽(2 번 홉) 2 ms 로 사내 구간은 정상입니다.
