## 5교시 · TCP

### 문제 5-1 · 직접 실행해 보기

- 출력 세 줄: True / False / 443
- 탐지 코드에서 플래그를 `==` 로 검사하면 어떤 일이 생기나요? 둘째 줄을 근거로 설명합니다.
  - 답: 플래그는 여러 개가 리스트에 들어 있어서, `==` 로 검사하면 리스트 전체를 글자 하나와 비교하게 된다. 그래서 둘째 줄처럼 항상 False 가 나온다. 에러가 나지 않기 때문에 공격이 와도 탐지 코드가 조용히 아무것도 잡지 못한다.

### 문제 5-2 · TCP 일까 UDP 일까

- ① ~ ⑤ 가 각각 TCP · UDP · ICMP 중 무엇인지: ① TCP ② UDP ③ TCP ④ UDP ⑤ ICMP
- ① 사진 파일 보내기가 TCP 인 이유는 무엇인가요?
  - 답: 사진은 조각이 하나라도 빠지면 깨지기 때문에, 받았는지 확인하고 안 왔으면 다시 보내는 TCP 를 쓴다.

### 문제 5-3 · 세 번의 순서 맞히기

- 세 패킷의 순서와 방향: (나) SYN 내 PC → 서버 · (다) SYN, ACK 서버 → 내 PC · (가) ACK 내 PC → 서버
- 🔍 연결을 맺을 때는 세 번인데, 끝낼 때는 왜 네 번인가요?
  - 답: 맺을 때는 서버가 「알았다(ACK)」와 「나도 연결하자(SYN)」를 한 번에 보낼 수 있어서 세 번이다. 끝낼 때는 서버가 「알았다(ACK)」는 바로 보내지만, 남은 데이터를 다 보낸 뒤에 「나도 끝(FIN)」을 따로 보내야 해서 네 번이다.

### 문제 5-4 · 같은 서버로 간 두 연결은 무엇이 다른가

- 두 연결에서 같은 것 · 다른 것: 같은 것 — 내 IP(192.168.0.15), 서버 IP · 포트(142.250.196.110:443) · 다른 것 — 내 쪽 포트(51234 / 51240)
- 같은 서버로 간 두 연결을 무엇으로 구별하나요?
  - 답: 내 PC 가 연결마다 다르게 고르는 임시 포트 번호로 구별한다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: TCP 는 세 번 신호를 주고받아 연결하고 네 번 주고받아 끊으며, 빠지면 안 되는 데이터는 TCP, 빠른 게 중요한 데이터는 UDP 를 쓴다.

## 최종 분석 — 7교시에 완성합니다

> 오늘 잡은 **내 HTTP 연결 하나**를 처음부터 끝까지 정리합니다. 위에서 적은 6-3 · 7-1 · 7-2 의 답을 다시 보며 씁니다.

### 1. 연결이 열리는 순간 — 3-way handshake

- 세 줄의 Source → Destination 과 Info: 192.168.100.33 → 172.66.147.243 `56708 → 80 [SYN]` / 172.66.147.243 → 192.168.100.33 `80 → 56708 [SYN, ACK]` / 192.168.100.33 → 172.66.147.243 `56708 → 80 [ACK]`
- 세 줄이 오간 뒤 두 컴퓨터는 어떤 상태가 되나요?
  - 답: 연결이 맺어진 ESTABLISHED 상태가 되어 데이터를 주고받을 수 있다. 실제로 바로 다음 4번 패킷에서 GET 요청을 보냈다.

### 2. 패킷 하나를 열어 본 값 — 6-3

- 출발지 · 목적지 IP (3층) · TTL · 출발지 · 목적지 포트 (4층): 192.168.100.33 → 204.79.197.222 · TTL 128 · 59679 → 443
- 목적지 포트를 보고 어떤 서비스로 가는 패킷인지 알 수 있나요? 4.1 표를 근거로 설명합니다.
  - 답: 4.1 표에서 443 은 HTTPS(암호화된 웹)이므로 웹 서버로 가는 패킷이라고 볼 수 있다. 다만 포트 번호만으로 통신 내용을 확정할 수는 없다.

### 3. HTTP 요청 — 7-2

- 요청 줄에서 그대로 보인 내용: GET /?q=network_day1 HTTP/1.1 — 검색어 network_day1
- 이것이 보안에서 문제가 되는 이유는 무엇인가요?
  - 답: HTTP 는 암호화하지 않아서 같은 망의 누구든 패킷을 잡으면 내용을 그대로 볼 수 있다. 검색어가 아니라 아이디 · 비밀번호였다면 그대로 도둑맞는다. 그래서 HTTPS 를 써야 한다.

### 4. 오늘 하루 정리

- 오늘 배운 것 가운데 가장 중요하다고 생각하는 것과 그 이유: 증상을 보고 OSI 층을 아래부터 좁혀 가는 방법이다. 「인터넷이 안 돼요」 한마디로 들어오는 신고도 ping · ipconfig · arp · netstat 결과로 어느 층에서 막혔는지 나누면 원인을 빨리 찾을 수 있고, Wireshark 로 그 값이 실제 패킷에 들어 있는 것까지 확인할 수 있기 때문이다.
