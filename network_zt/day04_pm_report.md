  - 쓸 내용: 「A 규칙 ○ · 허용 또는 차단」처럼 세 줄
  - 답:
    - A 규칙 3 · 허용
    - B 규칙 5 · 차단
    - C 규칙 5 · 차단

  - 쓸 내용: ① 두 요청에서 달라진 값 하나 ② 그 값 때문에 각각 몇 번 규칙에 맞았는지
  - 답: ① 「어디로」(목적지)가 다릅니다. A 는 업무 포털, B 는 웹메일입니다. ② A 는 3번(부산 지점 → 업무 포털 · 443)에 맞아 허용되고, B 는 부산 지점 → 웹메일 규칙이 없어 1 ~ 4번을 모두 지나 5번(any 차단)에 맞아 차단됩니다.

  - 쓸 내용: ① A ~ C 의 새 결과 ② `any` 규칙을 둘 위치와 이유
  - 답: ① A · B · C 모두 1번(any → any · any 차단)에 먼저 맞아 차단됩니다. ② `any` 규칙은 어떤 요청에든 맞으므로 맨 위에 두면 아래 허용 규칙이 하나도 쓰이지 못합니다. 그래서 맨 아래에 둡니다.

### 문제 5-2 · 허용된 연결과 막힌 연결을 Wireshark 로 재 보기

> ※ 아래 Time 값은 내 Wireshark 화면 값으로 바꿔 적습니다.

- (가-1) 80번 연결의 `[SYN]` 과 `[SYN, ACK]` 두 줄의 `Time` 값, 그리고 두 값의 차이(RTT)를 ms 로 적어 주세요.
  - 쓸 내용: `[SYN]` 줄의 `Time`, `[SYN, ACK]` 줄의 `Time`, 두 값의 차이를 ms 로 계산한 값
  - 답: [SYN] 0.000 / [SYN, ACK] 0.036 → RTT 36 ms
- (가-2) 81번 연결에서 SYN 이 몇 번 나갔는지, 줄마다의 `Time` 값, 상대에게서 온 것(SYN/ACK · RST · 없음), `curl` 의 마지막 문구를 적어 주세요.
  - 쓸 내용: ① SYN 횟수 ② 줄마다의 `Time` 값 ③ 상대에게서 온 것 ④ `curl` 마지막 문구 한 줄

- (나-1) 🔍 81번 연결은 3-way handshake 의 어디에서 멈췄나요? 5.2 의 두 방식 가운데 어느 쪽이고, 그렇게 판단한 근거 화면은 무엇인가요?
  - 쓸 내용: ① 멈춘 단계(SYN · SYN/ACK · ACK 가운데) ② 드롭 / 거부 가운데 하나와 근거 화면
  - 답: ① 첫 단계 SYN 에서 멈췄습니다. SYN/ACK 가 오지 않아 둘째 단계로 가지 못했습니다. ② 드롭입니다. Wireshark 에 `→ 81 [SYN]` 과 `[TCP Retransmission]` 줄만 반복되고 `81 →` 로 오는 SYN/ACK · RST 줄이 하나도 없었으며, curl 이 15초를 기다린 뒤 `(28)` 시간 초과로 끝났습니다. 같은 서버의 80번은 연결됐으므로 서버 · 내 PC 문제가 아닙니다.
- (나-2) 81번 SYN 줄의 `Time` 값으로 SYN 사이의 간격을 구해 적어 주세요. 간격은 일정했나요, 늘어났나요?
  - 쓸 내용: ① (가-2) 의 `Time` 값으로 구한 줄 사이 간격 두 가지(앞부분 · 뒷부분, 예: 1.0초, 2.0초) ② 간격이 일정했는지, 늘어났는지
  - 답: ① 앞부분 약 1.0초, 뒷부분 약 2.0초 → 4.0초 ② 간격이 점점 늘어났습니다. 답이 없는 원인이 혼잡일 수 있어서, 다시 보낼 때마다 기다리는 시간을 늘려 망 부담을 줄이기 때문입니다.
- (다) 아래 방화벽 로그의 14:05 네 줄을 `10.8.0.21` PC 쪽에서 패킷으로 보면 어떤 모습일까요? 무엇을 하려던 기록으로 보이는지, 다음에 어떤 기록을 확인하면 좋을지도 적어 주세요.
  - 쓸 내용: ① 패킷으로 보이는 모습(무엇을 보내고 무엇이 안 왔는지) ② 목적지 · 포트 · 간격으로 본 행동 ③ 다음에 확인할 기록
  - 답: ① 10.8.0.21 PC 에서는 서로 다른 서버 · 포트로 SYN 을 보냈지만 SYN/ACK 가 하나도 오지 않고 SYN 재전송만 반복되는 모습입니다. ② 1초 간격으로 관리 서버 SSH(22) · 관리 서버 웹(443) · 고객 DB(3306) · 다른 DB(5432)를 차례로 시도했으므로, 열린 관리용 · DB 포트를 찾는 내부 포트 스캔으로 보입니다. ③ 오전 4교시의 VPN 게이트웨이 접속 로그에서 14:05 무렵 10.8.0.21 을 받은 사용자 계정과 출발 공인 IP 를 확인합니다.
- (라) (선택) 사용자가 「회사 서버에 접속이 안 된다」고 합니다. 패킷만 보고 방화벽 문제인지 서버 문제인지 어떻게 나눌 수 있을까요?
  - 쓸 내용: 응답이 아예 없을 때 · RST 가 올 때 · SYN/ACK 가 올 때 각각 무엇을 의심하고 먼저 어디를 볼지. 선택 문항이라 안 쓰면 「선택 안 함」이라고 적습니다
  - 답: 응답이 아예 없으면(SYN 재전송만) 중간 방화벽의 드롭을 의심하고 방화벽 규칙 · 로그부터 봅니다. RST 가 오면 방화벽 거부이거나 서버에 그 포트를 받는 프로그램이 없는 것(닫힌 포트)이라 서버의 포트 · 프로그램 상태와 방화벽 거부 규칙을 함께 봅니다. SYN/ACK 가 오면 연결은 된 것이니 방화벽이 아니라 서버 프로그램 · 응용 계층 문제를 봅니다.

## 6교시 · 허용 목록 · 규칙 순서

### 문제 6-1 · 학원 방화벽은 허용 목록일까 차단 목록일까

> ※ 학원망 결과는 날마다 다를 수 있으니 내 화면 결과와 다르면 고쳐 적습니다.

- (가) 포트 443 · 445 · 3389 마다 「열림 · 드롭 · 거부」 판정과 근거(`curl` 문구 · Wireshark 화면)를 한 줄씩 적어 주세요.
  - 쓸 내용: 「443: 열림 — Port test successful!」처럼 포트마다 한 줄, 판정과 근거
  - 답:
    - 443: 열림 — `Port test successful!`, Wireshark 에 `443 → 내포트 [SYN, ACK]` 가 옴
    - 445: 드롭 — 5초 뒤 `curl: (28) …`, `[SYN]` 과 `[TCP Retransmission]` 만 있고 `445 →` 줄 없음
    - 3389: 열림 — `Port test successful!`, Wireshark 에 `3389 → 내포트 [SYN, ACK]` 가 옴
- (나) 🔍 이 결과로 보면 학원 방화벽은 허용 목록과 차단 목록 가운데 어느 쪽에 가까운가요? 근거가 된 포트를 들어 적어 주세요.
  - 쓸 내용: ① 허용 목록 / 차단 목록 / 알 수 없음 가운데 하나 ② 근거가 된 포트와 그 결과 ③ 안내 6.1 표의 어느 줄과 맞는지
  - 답: ① 차단 목록에 가깝습니다. ② 위험한 관리용 포트 3389 까지 열렸고 파일 공유 445 만 막혔습니다. ③ 6.1 표의 「규칙에 없는 새 서버 · 새 포트 → 차단 목록은 열린다」 줄과 맞습니다. 위험하다고 알려진 몇 개(445)만 막고 나머지(맨 아래 줄)는 허용하는 모습입니다.
- (다-1) 포트 세 개만 보고 내린 판단에는 어떤 한계가 있을까요? 더 확실하게 알려면 무엇을 더 해야 할까요?
  - 쓸 내용: ① 한계 한 가지 ② 더 해야 할 시험 한 가지
  - 답: ① 65,535 개 포트 가운데 세 개만, 목적지도 portquiz.net 하나만 시험해서 다른 포트 · 목적지별로 다르게 막는지 알 수 없습니다. ② 25 · 53 · 8080 · 8443 등 포트를 더 많이 시험하고, 다른 목적지에서도 같은 결과인지 확인합니다.
- (다-2) 6번 필터(`tcp.flags.syn == 1 && tcp.flags.ack == 0`)로 바꾸니 2번 필터 화면에서 어떤 패킷이 사라졌나요? 한 PC 가 여러 포트로 연결을 시작한 것을 찾을 때 이 필터를 쓰는 이유는 무엇일까요?
  - 쓸 내용: ① 사라진 패킷의 종류 ② 시작 SYN 만 모아 볼 때 알 수 있는 것
  - 답: ① 서버가 보낸 `[SYN, ACK]` · `[RST]` 와 연결 뒤의 ACK · 데이터 패킷이 사라지고, 내 PC 가 보낸 `[SYN]`(재전송 포함)만 남았습니다. ② 연결을 시작한 요청만 모이므로 한 출발지가 몇 개의 목적지 포트로 연결을 시도했는지 바로 셀 수 있어, 짧은 시간에 여러 포트로 SYN 을 보내는 포트 스캔을 찾기 쉽습니다.

### 문제 7-1 · 요구사항을 읽고 규칙표 직접 쓰기

  - 쓸 내용: 처음 점수 하나와 고친 횟수 하나
  - 답: 처음 점수 `점수: 1 / 8`, 규칙을 채운 뒤 1번 고쳐서 `점수: 8 / 8`
