### 문제 2-2 · 접속 요청 여섯 개를 5대 원칙의 칸으로 분류하기

- (가) 요청 ① ~ ⑥ 은 각각 5대 원칙 중 어느 칸에서 걸리나요? 걸리지 않고 통과하면 「통과」라고 적어 주세요.
  - 쓸 내용: 「①: … / ②: … / ③: … / ④: … / ⑤: … / ⑥: …」 여섯 개
  - 답: ①: ID (관리자 권한인데 MFA 없이 비밀번호만) / ②: Device (개인 노트북, 백신 꺼짐, 패치 미적용) / ③: Application (인사 시스템 앱 권한 없음) / ④: Network (앱을 거치지 않고 서버 구역 DB 에 직접 연결) / ⑤: Policy (해외 IP · 새벽) / ⑥: 통과
- (나) 🔍 요청 ⑤ 는 ID · Device · Application 이 모두 정상인데 왜 Policy 칸에서 걸리나요?
  - 쓸 내용: ① 정상인 것 ② 평소와 달라진 상황 ③ Policy 칸이 하는 일
  - 답: ① 비밀번호+MFA(ID), 최신 회사 노트북(Device), 영업 앱 권한(Application)이 모두 정상이다. ② 평소 서울에서만 접속하던 사용자가 새벽 03:00 에 해외 IP 로 접속했다. ③ Policy 칸은 시간·위치·위험도 같은 **상황**을 보고, 평소와 다르면 추가 인증을 요구하거나 막는다.
- (다) 요청 ③ 과 ④ 는 둘 다 가면 안 되는 곳에 닿으려는 시도인데 왜 서로 다른 칸에서 걸리나요?
  - 쓸 내용: ① ③ 이 확인하는 것 ② ④ 가 확인하는 것
  - 답: ① ③ 은 Application 칸으로 「이 앱의 이 기능을 쓸 권한이 있는가」를 확인한다(마케팅팀은 인사 시스템 앱 권한이 없음). ② ④ 는 Network 칸으로 「요청이 필요한 자원에만 닿는가」를 확인한다(앱을 거치지 않은 DB 직접 연결은 구역을 나눠 두면 아예 닿지 않음). 권한 문제인지 경로 문제인지에 따라 고칠 곳이 다르다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 한 줄씩은 정상으로 보이는 기록도 맡은 자원과 대조하고 합산하면 이상이 보인다는 것. 12·14~17번처럼 로그인과 기기가 모두 정상이어도 Application·Policy 칸이 비어 있으면 그대로 통과한다는 점이 기억에 남는다.
