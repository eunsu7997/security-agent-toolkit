## 5교시 · 왜 도커인가 · 이미지와 컨테이너 · 같이 설치하기

### 문제 5-1 · 설치를 확인하고 첫 컨테이너 실행하기

- (가) `docker --version` 으로 나온 값을 적어 주세요.
  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답: Docker version 29.8.2, build 7fc2dff
- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.
  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답: ① 터미널의 docker 명령(클라이언트)이 도커 엔진(데몬)에 요청을 보냈다. ② 엔진이 PC에 hello-world 이미지가 없어서 Docker Hub 에서 받아 왔다. ③ 엔진이 받은 이미지로 컨테이너를 만들어 실행했다. ④ 컨테이너가 "Hello from Docker!" 글자를 출력하고, 엔진이 그것을 클라이언트를 거쳐 터미널로 보내 줬다.
- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?
  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답: ① images 에는 hello-world:latest 가 보였고, 이것은 이미지(실행할 프로그램을 묶어 둔 읽기 전용 꾸러미)다. ② ps -a 에는 thirsty_merkle · jovial_edison 두 줄이 보였고, 이것은 컨테이너(이미지를 실제로 실행한 것)다. ③ 이미지는 설계도처럼 하나만 있고 읽기만 되며, 컨테이너는 그 이미지로 실행할 때마다 하나씩 생긴다. 그래서 이미지 1개(hello-world)에서 컨테이너 2개가 만들어졌고, 컨테이너는 끝나도(Exited) 목록에 남는다.
- (라) 🔍 `docker images` 출력을 붙여 넣고, `hello-world` 줄의 `IMAGE` · `ID` · `EXTRA` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `IMAGE` · `ID` · `EXTRA` 의 값과 뜻
  - 답: IMAGE = hello-world:latest (이미지 이름:태그, 태그를 안 줘서 latest 가 붙음). ID = 11a3eb1597e8 (이미지 고유 번호, 번호가 같으면 같은 이미지). EXTRA = U (이 이미지로 만든 컨테이너가 있다는 표시, 꺼진 컨테이너 포함).

```
IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-world:latest   11a3eb1597e8       25.9kB         9.49kB   U
```

- (마) 🔍 `docker ps -a` 출력을 붙여 넣고, `hello-world` 줄의 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `STATUS` · `PORTS` · `NAMES` · `IMAGE` 의 값과 뜻
  - 답: STATUS = Exited (0) 5 minutes ago (정상으로 끝나고 꺼진 상태, 0 이라 오류 없음). PORTS = 비어 있음 (내 PC와 연결된 포트가 없어서 밖에서 접속할 길이 없음). NAMES = thirsty_merkle, jovial_edison (이름을 안 줘서 도커가 무작위로 붙인 이름, stop · rm 등에 이 이름을 씀). IMAGE = hello-world (이 컨테이너를 만든 이미지).

```
CONTAINER ID   IMAGE         COMMAND    CREATED             STATUS                     PORTS     NAMES
fc74ceecbfcc   hello-world   "/hello"   About an hour ago   Exited (0) 5 minutes ago             thirsty_merkle
e31ccf66df46   hello-world   "/hello"   About an hour ago   Exited (0) 5 minutes ago             jovial_edison
```

  - 쓸 내용: ① nginx 가 정하는 것 ② 1.28 이 정하는 것
  - 답: nginx 는 어떤 이미지(프로그램)를 쓸지, 즉 이미지 이름을 정하고, 1.28 은 그 이미지의 어느 버전(태그)을 쓸지 정한다.
- (나) 🔍 `docker pull nginxx` 를 쳤을 때 나온 오류 문구와 그 뜻을 적어 주세요.
  - 쓸 내용: ① 오류 문구 ② 뜻 ③ 고치는 방법
  - 답: ① pull access denied for nginxx, repository does not exist or may require 'docker login' (태그를 안 써서 Using default tag: latest 도 같이 나옴). ② Docker Hub 에 nginxx 라는 이미지 저장소가 없거나, 있어도 로그인해야 받을 수 있다는 뜻이다. 여기서는 이름 오타로 없는 이미지를 요청한 것이다. ③ 이름을 nginx 로 바로 쓰고, 버전을 고정하려면 nginx:1.28 처럼 태그까지 쓴다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(도커를 쓰면 무엇이 같아지는지)
  - 답: 모든 PC에서 같은 이미지(예: nginx:1.28)를 받아 컨테이너로 실행하면 버전과 설정이 어느 PC에서나 똑같은 환경이 되니, 관제 도구도 이미지로 배포하시길 권합니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: docker run 으로 만든 컨테이너는 끝나도 지워지지 않고 ps -a 에 남으며, 이미지 하나로 컨테이너를 여러 개 만들 수 있다는 것을 알게 되었다.

## 6교시 · nginx 서버 켜고 접속 기록 읽기

### 문제 6-1 · 포트 없이 켜 보고, 포트를 연결해 접속하고, 기록 읽기

- (가) 포트 없이 켠 `web` 에 접속했을 때 어떻게 되었는지 적어 주세요.
  - 쓸 내용: 접속했을 때 나온 화면이나 오류와 `docker ps` 의 PORTS 열
  - 답: 접속이 안 되고 연결할 수 없다는 오류가 났다(curl 은 연결 실패, exit 7). docker ps 의 PORTS 열에는 `80/tcp` 만 있고 `->` 가 없었다. 컨테이너는 Up 인데 내 PC 포트와 연결이 없어서 밖에서 닿을 길이 없다.
- (나) 🔍 `-p 8080:80` 이 하는 일을 내 PC의 포트와 컨테이너의 포트로 나눠 설명해 주세요.
  - 쓸 내용: ① 내 PC 쪽 포트 ② 컨테이너 쪽 포트 ③ 연결이 하는 일
  - 답: ① 앞의 8080 은 내 PC 의 포트. ② 뒤의 80 은 컨테이너 안 nginx 가 듣는 포트. ③ 내 PC 8080 으로 온 요청을 컨테이너 80 으로 넘겨 준다(포트 포워딩). 연결 뒤 docker ps 의 PORTS 가 `0.0.0.0:8080->80/tcp` 로 바뀌었고 http://127.0.0.1:8080 에서 Welcome to nginx! 가 나왔다.
- (다) 🔍 `docker logs web` 출력에서 `GET /` 줄 하나를 붙여 넣고, 접속자 주소 · 시각 · 요청 · 응답 번호를 찾아 적어 주세요.
  - 쓸 내용: ① `GET /` 줄 ② 접속자 주소 · 시각 · 요청 · 응답 번호 네 가지
  - 답: 접속 전에는 GET 줄이 0개(시작 메시지만)였고, 접속 후 아래 줄이 생겼다. 접속자 주소 172.17.0.1 (도커가 붙인 사설 주소) · 시각 19/Oct/2026:06:50:04 +0000 · 요청 "GET / HTTP/1.1" (첫 화면 요청) · 응답 번호 200 (성공, 615 글자 전송). 접속 도구는 브라우저 대신 curl 이라 마지막 칸이 curl/8.21.0 이다.

```
172.17.0.1 - - [19/Oct/2026:06:50:04 +0000] "GET / HTTP/1.1" 200 615 "-" "curl/8.21.0" "-"
```

### 문제 6-2 · 컨테이너 안을 들여다보고, 끄고, 지우기

- (가) 컨테이너 안에서 `ls /usr/share/nginx/html` 로 본 파일 이름을 모두 적고, 그중 브라우저의 첫 화면이 어느 파일인지 적어 주세요.
  - 쓸 내용: ① 파일 이름 모두 ② 첫 화면 파일
  - 답: ① 50x.html, index.html ② index.html (주소 `/` 로 접속하면 보이는 Welcome to nginx! 가 이 파일. 50x.html 은 서버 오류 안내용).
- (나) 🔍 `docker stop web` 뒤에 `docker ps` 와 `docker ps -a` 에 각각 `web` 이 보이나요? 차이를 설명해 주세요.
  - 쓸 내용: ① stop 뒤 ps 에 보이는지 ② ps -a 에 보이는지 ③ 차이의 이유
  - 답: ① docker ps 에는 web 이 안 보였다(목록이 비어 있음). ② docker ps -a 에는 `Exited (0)` 으로 보였다. ③ ps 는 켜져 있는 컨테이너만 보여 주고, ps -a 는 꺼진 것까지 모두 보여 준다. stop 은 끄기만 하고 지우지는 않아서 컨테이너가 남아 있다. (끈 뒤 접속도 안 됨)
- (다) 🔍 같은 이름으로 다시 `run` 했을 때 나온 오류 문구와, `docker rm` 이 필요한 이유를 적어 주세요.
  - 쓸 내용: ① 오류 문구 ② rm 이 필요한 이유
  - 답: ① docker: Error response from daemon: Conflict. The container name "/web" is already in use by container "19468670856e…". You have to remove (or rename) that container to be able to reuse that name. ② 꺼진 web 도 지워지지 않고 이름을 차지하고 있어서, 같은 이름을 다시 쓰려면 docker rm web 으로 지워야 한다. 지운 뒤에는 같은 명령이 오류 없이 켜졌다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(켜는 명령 · 기록 보는 명령 · 정리 방법)
  - 답: `docker run -d --name web -p 8080:80 nginx:1.28` 로 켜고 http://127.0.0.1:8080 으로 접속하면, `docker logs web` 에 접속자 주소·시각·요청·응답 번호가 한 줄씩 남으며, 다 쓰면 `docker stop web` 후 `docker rm web`(또는 `docker rm -f web`)으로 정리합니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 컨테이너가 Up 이어도 -p 로 포트를 연결하지 않으면 접속이 안 되고, 접속 기록 줄은 누군가 접속해야 생긴다는 것을 알게 되었다.

## 7교시 · 내 페이지 연결 · 두 서버 · 올리기

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답: ① 컨테이너 안에서 index.html 을 `<h1>inside</h1>` 로 바꾸자 화면에 inside 만 보였다. ② docker rm -f web 으로 지우고 다시 켜자 화면이 다시 Welcome to nginx! 로 돌아왔다(고친 것이 사라짐).
- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답: ① 고친 파일은 이미지가 아니라 그 컨테이너에만 저장되어서, 컨테이너를 지우면 함께 사라지고 새 컨테이너는 이미지의 원래 파일로 시작하기 때문이다. ② -v 로 내 PC 폴더를 연결하면 파일이 컨테이너 밖(내 PC)에 있어서 컨테이너를 지워도 남고, 내 PC 에서 파일을 고치면 서버를 다시 켜지 않아도 바로 화면에 반영된다.
- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답: ① 오류는 없었는데 site-one 이 아니라 Welcome to nginx! 가 나왔다. ② Git Bash 가 -v 뒤의 컨테이너 쪽 경로를 `C:/Program Files/Git/usr/share/nginx/html` 같은 윈도 경로로 바꿔서, 연결이 엉뚱한 곳에 되었기 때문이다. 명령 앞에 MSYS_NO_PATHCONV=1 을 붙이면 경로가 안 바뀌어 site-one 이 보였다.

### 문제 7-2 · 서버 두 대를 띄워 포트로 구분하고, 파일을 고쳐 바로 반영되는지 보기

- (가) 두 주소(`8080` · `8081`)에서 보이는 화면을 각각 적어 주세요.
  - 쓸 내용: 두 주소의 화면 문구
  - 답: 8080 → site-one · 첫 번째 서버입니다 / 8081 → site-two · 두 번째 서버입니다
- (나) 🔍 `docker ps` 의 PORTS 열에서 두 서버를 구분해 주는 것은 무엇인가요?
  - 쓸 내용: PORTS 열에서 서버를 구분하는 값
  - 답: 내 PC 쪽 포트 번호다. web-one 은 `0.0.0.0:8080->80/tcp`, web-two 는 `0.0.0.0:8081->80/tcp` 로 IMAGE(nginx:1.28)와 컨테이너 안 포트(80)는 같고 내 PC 포트(8080 · 8081)만 다르다.
- (다) 🔍 `:ro` 는 무슨 뜻이고, 왜 읽기 전용으로 연결하나요?
  - 쓸 내용: ① :ro 의 뜻 ② 읽기 전용으로 연결하는 이유
  - 답: ① read-only, 컨테이너가 연결된 폴더를 읽기만 하고 바꾸거나 지우지 못한다는 뜻이다. ② 서버는 페이지를 보여 주기만 하면 되므로, 컨테이너가 침해되거나 실수해도 내 PC 의 원본 파일이 바뀌지 않도록 일에 필요한 만큼만 허용(최소권한)하기 위해서다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(두 서버를 어떻게 띄웠는지)
  - 답: 같은 nginx:1.28 이미지로 web-one(8080, site-one 폴더)과 web-two(8081, site-two 폴더)를 `-v …:ro` 로 내 폴더를 읽기 전용 연결해 띄웠고, 포트로 서버를 구분하며 내 PC 의 파일만 고치면 다시 켜지 않아도 바로 반영됩니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
